## 1. 极短伴奏音

问题来自两步：拍点命中了前一个低音最后几毫秒，生成了新伴奏事件；节奏整理和段落裁剪后，剩余时长没有复检。

现在选低音时先检查有效重叠长度；仅剩尾巴的候选不再使用，附近存在可靠新起音时可选择它，并保留真实起音时间。生成与最终裁剪后都要求伴奏时长至少为 `max(80 ms, 用户最短音符)`，不把几毫秒尾音虚构延长。最终键位与复音约束在裁剪、过滤之后执行，避免无效残片挤占有效伴奏。

| 可定位实例 | 修复前时长 | 修复后 |
|---|---:|---|
| 租购 215.969 秒 | 1.20 ms | 不再保留该残片 |
| 海屿你 52.524 秒 | 6.46 ms | 不再保留该残片 |
| 海屿你 174.126 秒 | 3.56 ms | 不再保留该残片 |
| 好想爱这个世界啊 64.459 秒 | 51.41 ms | 不再保留该残片 |

最终伴奏总数：租购 87 → 87，海屿你 207 → 210，好想爱这个世界啊 29 → 29。总数没有简单减少 19，因为附近有效低音可以替代残片，原来受无效残片占位或段落边界限制的部分伴奏也得以保留。总音数增加不作为准确率提升的证据。

## 2. 段落切换截断长音

## 3. 拖动试听丢失持续音

原排程只发送光标之后的起音事件。拖入正在持续的音符时，其起点已在光标之前，因此剩余部分不会播放。

现在定位或暂停恢复后，先清除旧声音，再找出仍在持续的音，按“音符结束时间 − 光标位置”恢复剩余时值，计入播放倍率。光标恰好落在起音上的音符只触发一次，已被同键新起音替代的旧音不会复活。持续型音色（如长笛）恢复；钢琴等自然衰减音色不补打新起音。

使用两版真实 `Player._run`、确定性 2 ms 时钟、实际长笛 Mixer，给两版输入**同一份修复后曲谱**，只开启主旋律，从以下位置输出 3 秒，隔离排程修复：

| 歌曲 / 拖动位置 | 修复前行为 | 修复后剩余时值 | 前 100 ms RMS：前 → 后 |
|---|---|---:|---:|
| 租购 / 237.000 秒 | 漏掉当前长音 | 1585.03 ms | 0 → 0.01921 |
| 海屿你 / 207.000 秒 | 漏掉当前长音 | 1600.00 ms | 0 → 0.06740 |
| 好想爱这个世界啊 / 80.400 秒 | 漏掉当前长音 | 637.64 ms | 0 → 0.01921 |

试听页末尾有独立“拖动对照”，播放真实排程渲染结果。常规片段的浏览器进度条仅定位 WAV，不冒充应用排程测试。恢复的是持续发声及剩余时长，不是无缝续接原样本波形相位。Windows 游戏通路仅在用户已开启长音模式时恢复；本轮有单元验证，没有 Windows 游戏实机验证。
