# 设备预检与整曲和弦模式验证

本文记录首版 `rich-harmony-1`。后续伴奏音区、密度与声能问题及修正结果见
[伴奏平衡验证](TRANSCRIPTION_BALANCE_REVIEW_2026-10-20.md)；这里的原始数据保留用于前后对照。

## 交付

- 新增 `rich_chords`「主旋律＋和弦」，全部 37 种内置音色可选；旧稀疏和弦、单音及推荐模式不变。
- `--probe-devices` schema 1 返回 CPU、GPU 运算探测、各阶段预计设备和限制原因。策略为 `stage-probe-2`。
- Hybrid 3.2.0、MuScriptor 2.2.0；兼容 Hybrid 3.0.0 / 3.1.0 和 MuScriptor 2.0.0 / 2.1.0。
- 自动模式对结构化 GPU 显存／兼容错误仅用 CPU 重试失败阶段一次；重试失败不递归重试。
  CPU 显式选择、取消、模型缺失和非设备错误不重试。阶段输出和缓存记录实际设备及回退原因。
- 和声特征修订 `hybrid-features-2` 保存已计算的色度与和声能量。新编配修订 8，策略 `rich-harmony-1`。
  旧草稿可直接从原始事件提取和声证据，无须重新跑模型；打开草稿不自动重写，编辑稿另存版本。

## 编配行为

旋律选择、移调和键位映射沿用原流程。伴奏独立读取非鼓、非人声的背景音符及低音，
保留原始起音和来源；明确的大小三和弦可补全，缺少五音时须有根音低音和三音证据。
证据模糊时只保留符合音域／冲突限制的原始支撑，并记录待核对区间。

可靠拍点下按原曲密度和持续／衰减音色选择柱式、分解或低音支撑，不再使用两拍／四拍稀疏间隔。
拍点不可靠时不生成细分节奏。最多四个同时按键，旋律优先，同键重叠被排除；
强音尾用于检查相邻和声冲突，较弱自然衰减允许叠响。该上限指按键／谱面声部，不等于所有自然音尾数量。

旋律缺失与音频静音分别处理。前奏、间奏、尾奏和旋律待修正处允许独立伴奏；
原音频静音和人工休止不补音。补全音记录和声区间、证据事件及编配事件标识，原始 MIDI 保持模型事件。
局部精修保护选区外及跨界音符，检查生成音的边界、和声和同时按键冲突。

## 组件与复现

构建入口增加冻结设备协议验证，并为两个打包任务隔离 PyInstaller 缓存，避免并发损坏缓存。

```sh
.venv/bin/python scripts/prepare_hybrid.py --skip-install --package
.venv/bin/python scripts/prepare_muscriptor.py --skip-install --package
.venv/bin/python scripts/evaluate_rich_harmony.py
```

本次本地产物位于 `dist/AutoSkyPlay-Hybrid-3.2.0-macos-arm64.zip` 和
`dist/AutoSkyPlay-MuScriptor-2.2.0-macos-arm64.zip`，各附 SHA256 校验文件。
没有创建 GitHub Release 或 Windows 安装包。
