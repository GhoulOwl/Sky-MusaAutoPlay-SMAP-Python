# 主唱去和声与器乐分轨识谱

分支：`codex/multistem-transcription`。参考 StemDeck 修订
`5f9405ca68ac31b31ae07ac416141d4d1f7b5f3a` 的分离思路；实现沿用本项目的离线工作进程、
固定权重校验、原始事件与编配分离、分阶段缓存和草稿管理。

## 新任务流程

1. HTDemucs-6s：人声、鼓、贝斯、吉他、钢琴、其他。保留 44.1 kHz 双声道浮点输出，
   不逐轨归一化；4 秒模型片段、30 秒外层块和 1 秒上下文继续控制内存。
2. Karaoke 2：仅对已分离的人声运行。模型的直接输出是 Instrumental，在此输入中对应和声残余；
   从输入减去补偿后的残余得到主唱。保存同长度的主唱、和声浮点文件；不保证零串音或无主唱损失。
3. GAME medium 识别主唱；MuScriptor small / medium 分别识别贝斯、吉他、钢琴、其他。
   鼓和和声不进入音高识别分支。每轨保留实际输入来源，模型乐器标签仍独立记录。
4. 所有分支验证时间范围后统一编配。可靠主唱优先，无主唱段落选择连续器乐主题。
   伴奏继续遵守光遇音域、主旋律保护、音尾和同时按键限制。
   跨轨同音／八度叠奏在和弦证据中按音级覆盖时间计票，避免重复数量扩大投票；原始事件不删除。

“其他”是独立输入和缓存阶段，不并入吉他或钢琴。它可以提供弦乐、合成器等主题与伴奏候选。
对器乐候选使用自身分轨能量作过滤证据，混音响度不能替代自身分轨支持。

## 节奏与调性

优先使用本地 Beat This! final0 读取原混音的拍点／小节首拍，保留现有鼓轨／混音 librosa 结果作对照与回退。
权重固定并校验；将已打开的文件传给模型，避免缺失路径触发其在线下载分支。
检测器不可用时记录原因并回退；显式 `--beat-detector model` 不可用时报错。
半速／倍速分歧会降低自动整理的内部可信度并提示人工复核，该分数不代表准确率。
只允许粗拍点附近最多 20 ms 的局部起音细化，不自动填补中间缺口或外推头尾拍点。

“查看／修正共享拍点”可按选段内秒数添加、修改、删除拍点，以及隔拍／插拍。
修改后另存草稿版本，原始模型音符不改写；声学 chroma 按原区间重采样，缺乏覆盖的区间不补造和声证据。
小节首拍只显示模型候选，不推断固定 4/4 拍；手动修改拍点后清除旧小节首拍，防止错配。

调性基于器乐 chroma、低音和可证实的全曲首尾，返回前三个候选、相近候选歧义与分析范围。
以源文件的真实长度判断是否到达全曲结尾，不能把调用者传入的选段时长当作全曲长度。
调性排名不是准确率，不覆盖用户移调，也不替代现有光遇音域与黑键代价计算。

## 兼容与准备

4.0.0 有独立模型目录 `build/multistem-models`，固定资产合计约 189 MB（十进制），
包含 HTDemucs-6s、Karaoke 2、Beat This!，不含已有 GAME / MuScriptor 权重。
主程序仍不导入 PyTorch；运行组件顺序启动每个工作进程，结束后释放模型。
ONNX Runtime 当前锁定 CPU 发行包；Karaoke 自动模式如实报告 CPU，不因 PyTorch CUDA 可用而虚报加速。
Demucs / GAME 的 MPS 策略未变，仍使用 CPU；MuScriptor 保留原 MPS / CUDA 支持。

```sh
PYTHONPATH=src uv run python scripts/prepare_hybrid.py
PYTHONPATH=src uv run python scripts/prepare_hybrid.py --skip-install --package
PYTHONPATH=src uv run python scripts/run_hybrid.py /path/to/song.wav \
  --data /path/to/app-data --output /path/to/result --start 40 --length 12 --device cpu
```

3.0.0 / 3.1.0 / 3.2.0 组件仍可安装和使用原流程。安装旧组件不会凭空获得新分离能力，界面明确提示升级。
已有草稿不自动转换；新分轨随派生音频预算清理，原始事件、用户修改和源音频仍长期保留。
分离、去和声、特征、人声、四组器乐分别缓存；失败或取消的阶段不发布缓存和完整结果。

## 验证范围

新增回归覆盖：主唱来源、鼓与和声排除、四组器乐独立输入（含“其他”）、选段入点、
分支缓存与失败恢复、半速／倍速分歧、缺模型回退、拍点编辑与声学证据重采样、跨轨重复计票、
仅“其他”轨承载主题、4.0 组件资产校验。保留原有完整回归。

首个真实音频为既有回归音源《海屿你》的 40–52 秒选段，CPU 初次完整运行约 48 秒，
得到主唱、贝斯、吉他、钢琴、其他五个音高事件分支，Beat This! 正常运行。
同一选段不构成准确率验证；没有逐音标注，不将候选数量变化解释为准确率提升。
模型输入归一化／复原和跨窗口重建另用 13 秒双声道信号检查，保留超 1 浮点峰值和准确样本数。
实际产物及构建日志保存在 `artifacts/multistem-2026-10-29/`（不入版本库）。

最终验证：470 项测试通过，Ruff 和 Git 空白检查通过。修正选段范围判定后，《海屿你》同一
12 秒选段源码运行约 38.3 秒；再次运行八个阶段全部命中缓存，约 0.32 秒，原始事件与分析数据一致。
macOS arm64 4.0.0 ZIP 通过实际组件导入，再用冻结引擎处理《好想爱这个世界啊》12 秒选段，
约 34.3 秒完成五个音高事件分支和神经拍点分析。主唱＋和声重组与输入混合人声的最大误差
在两段中分别约为 1.49e-8 / 2.98e-8；所有分轨样本数一致。
工作台、拍点编辑器和草稿保存做了离屏 UI 检查。Windows CUDA 与长选段的真机验证不在本次实测范围。

UVR 模型分发许可的已知边界记录在 `THIRD_PARTY_NOTICES.md`。本次未向外部发布。
